## Mobile app (apps/mobile)

This section applies to `apps/mobile/`. Mobile does not use `packages/ui/components` or `packages/ui/features`, but the component reuse, accessibility, state, and feedback requirements applicable to all interfaces in [UI development](../chorus-ui/SKILL.md#ui-development), the requirements for mobile text fields in [Input methods and text input](../chorus-ime/SKILL.md#input-methods-and-text-input), and [Internationalization](../chorus-i18n/SKILL.md#internationalization) also apply. Read them before changing mobile UI or text.

### Expo and mobile

- Each Expo SDK version introduces incompatible changes. Before using Expo APIs or configuration, read the versioned documentation (`https://docs.expo.dev/versions/v<major-version>.0.0/`) for the `expo` major version in [apps/mobile/package.json](../../../apps/mobile/package.json). Find other topics through the index at `https://docs.expo.dev/llms.txt`.
- See "Key architecture patterns" in [Project structure and architecture](../chorus-architecture/SKILL.md#project-structure-and-architecture) for the routes directory and layout files. Keep components, hooks, utility modules, and test files outside the routes directory.
- Native directories are generated by Expo prebuild; do not commit `ios/` or `android/`. Maintain native changes through application configuration and config plugins, not by directly editing generated files. Native projects are generated in the repository's GitHub Actions workflow and built and signed with Xcode and Gradle, without depending on EAS services.
- Install Expo and native module dependencies at the repository root with `pnpm --filter mobile exec expo install <dependency>`, preferring versions in Expo's compatibility list.
- If the list does not cover a dependency or another version is needed, check official compatibility notes for that SDK, React Native, and the dependency; successful installation does not prove compatibility.
- After changing mobile dependencies or upgrading the Expo SDK, run `pnpm --filter mobile exec expo install --check` to confirm dependency versions are compatible with the current SDK.
- Expo Go contains only its bundled native modules. After adding or upgrading a dependency containing native code, verify with a development build (`pnpm --filter mobile exec expo run:ios` or `pnpm --filter mobile exec expo run:android`); opening it in Expo Go does not count as verification. Development builds open and activate simulator windows, so run them only when the user asks; otherwise mark them as unverified in the result.
- Store credentials and device keys in system secure storage (such as `expo-secure-store`), not ordinary storage. Validate deep-link parameters as untrusted input and do not let them directly trigger actions with side effects. Push notifications must not contain sensitive content such as message bodies.
- When running mobile E2E locally, prepare devices without windows as required by "Do not disturb the foreground" in [Testing and verification](../chorus-testing/SKILL.md#testing-and-verification).
- For iOS, boot with `xcrun simctl boot <udid>`, install with `xcrun simctl install <udid> <App.app>`, then run `maestro --device <udid> test <flow>`.
- For Android, start with `emulator -avd <name> -no-window -no-audio -no-boot-anim -no-snapshot-save -port <port>`, install with `adb -s emulator-<port> install <apk>`, then run `maestro --device emulator-<port> test <flow>`.
- Do not prepare E2E devices using `maestro start-device`, `pnpm dev:mobile:ios`, or `pnpm dev:mobile:android`.
- Shut down only devices you started (`xcrun simctl shutdown <udid>` or `adb -s emulator-<port> emu kill`).
